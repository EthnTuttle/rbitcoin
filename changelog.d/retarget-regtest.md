- **`--retarget-regtest` turns regtest difficulty retargeting on.** `--retarget-regtest` (conf `retarget_regtest`, regtest only, not a Bitcoin Core option) replaces regtest's fixed difficulty with a fixed lab schedule: a 10 s target spacing, a 240 s target timespan (a 24-block adjustment interval), no min-difficulty blocks, and BIP94 off. A `0x1e7fffff` difficulty floor (~2^17 header hashes per block) is both the easiest target a retarget may clamp to and the default difficulty of the first period; `--regtest-pow-bits` then overrides that first-period initialization and must be at least as hard as the floor. The floor exists because the regtest pow limit sits just under 2^256, so the 256-bit retarget multiply overflows there — debug builds assert, release builds wrap (`docs/operator/operations.md` owns the mechanism) — while every target at or below the floor stays far below the overflow. A datadir mined under default regtest is outside the profile's contract; start a fresh datadir. Default regtest is unchanged: without the flag, difficulty stays fixed as before. `getblockchaininfo` gains a `consensus` object (not a Bitcoin Core field) naming the effective profile — network, genesis hash, pow limit and retarget floor (bits and target), spacing, timespan, adjustment interval, retarget flags, `regtest_pow_bits_overlay` (hex or null), subsidy and maturity, and buried activation heights — so a harness can fingerprint the chain it is talking to.
